## User finding

The V0.7 preview fails the physical/user-facing visual gate. El Toro reads as a near-reskin of Juanchi: materially similar body construction, head/face language, stance and silhouette with identity carried too heavily by shirt/accessory changes. The user also requires the same visual-quality correction across the existing roster.

This is not a polish request. It is a bounded repair of the already-frozen V0.7 requirement that fighters be recognizable procedural in-game characters.

## Goal

Upgrade the procedural character pipeline and all four released fighter rigs so character identity comes from body structure, silhouette, posture and motion — not primarily from clothing text/colors/accessories.

Released roster:
- Camaleoni
- Supernariz
- Juanchi
- El Toro

## Tooling already bootstrapped on the branch

Read `tools/character-pipeline-v2/README.md`.

Available reproducible/free authoring aids:
- Synfig / Synfig Studio
- Inkscape
- FFmpeg
- ImageMagick
- optional OpenToonz authoring lane

External tools are authoring aids only. Runtime remains procedural TypeScript + Canvas2D. Raster/reference exports remain prohibited as runtime fighter sprites.

## Required implementation

1. Introduce a reusable structural rig/profile layer that can represent materially different:
   - head width/height/profile;
   - neck/shoulder width;
   - torso width/length/mass;
   - arm/forearm thickness;
   - hip/leg proportions;
   - stance width/crouch/lean;
   - center-of-mass bias;
   - character-specific silhouette accents.

2. Re-author all four released fighters against that system.
   - They must not collapse onto one shared body template with cosmetic overrides.
   - Shared renderer primitives are encouraged; shared visual anatomy is not mandatory.

3. El Toro must read as:
   - broad / heavy / planted;
   - top-heavy rugby line-breaker;
   - wider shoulders and torso;
   - heavier limbs and lower planted base;
   - distinct head/hair profile from Juanchi;
   - recognizable without shirt text, scarf, colors or effects.

4. Juanchi must remain visually distinct from El Toro through body structure and stance, not merely outfit.

5. Camaleoni and Supernariz receive the same structural review so the released roster has four distinct neutral silhouettes.

6. Portrait renderers must derive from the same fighter identity/profile. Do not create separate unrelated portrait art.

7. Animation:
   - neutral/walk/backwalk/start/stop must reflect each fighter's mass and posture;
   - normals/Specials/Ultimates must remain readable with effects disabled;
   - preserve simulation timing and combat truth;
   - no gameplay/balance changes.

8. Preserve the existing `portraitKey` / PortraitRenderer consumer seam unless a real blocker proves it insufficient. If it must change, stop and raise a cross-role finding before changing Brancaforte-owned UI.

## Hard visual gates

A fighter fails if:
- a neutral black silhouette is easily confusable with another released fighter;
- character identity depends mainly on text/color/accessories;
- El Toro can plausibly be described as a Juanchi reskin;
- body proportions are copied from another fighter without deliberate authored reason;
- attack body motion becomes unreadable when effects are disabled.

## Evidence required

- exact commit SHA;
- full tests + build;
- runtime scan proving no fighter/reference raster loading;
- four-fighter neutral silhouette comparison;
- four-fighter normal-color comparison;
- El Toro vs Juanchi side-by-side at gameplay scale;
- effects-disabled action/pose evidence for representative normal + Special + Ultimate;
- phone-landscape screenshot/smoke evidence;
- note which external authoring tools were actually used vs merely available.

## Prohibited

- raster sticker fighters;
- runtime Synfig/OpenToonz/Rive dependency;
- gameplay value changes;
- changing hitboxes/damage/stun/move legality from renderer;
- CSS/DOM fighter art;
- inventing a new engine migration in this repair.
