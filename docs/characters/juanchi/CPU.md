# Juanchi CPU Contract

Juanchi CPU uses delayed public-snapshot perception. No raw input oracle, future state or frame-perfect retry loops.

## Identity

CPU should express:
- mid-range ball setup;
- movement that changes the return path;
- occasional approach behind ball pressure;
- short grounded conversion;
- Fricción only when commitment is plausible;
- Ultimate only from readable viable ranges.

## Fairness

The CPU must not:
- perfectly dodge its own return geometry;
- know future opponent inputs;
- instantly react every frame to jump/Ultimate cues;
- throw a second ball while one is active;
- ignore ball rearm;
- use cap capture with hidden homing;
- select mathematically optimal action every decision.

## Data-driven tactics

Preferred ranges, action weights, visible-cue delays and availability belong in fighter content/tactics data rather than identity branches in CpuController.

All seeded behavior remains deterministic for identical inputs/seeds.

## QA

Include Juanchi in all ordered roster matchups and the configured V0.6 seed matrix. Do not impose a win-rate quota; inspect variety, legal resource use, repeated-action pathologies and obvious deterministic slot bias.
